# ADR-0003: Human-in-the-loop для AI-записей

- Статус: принято
- Дата: 2026-08-19

## Контекст

AI может предложить изменения CMS и CRM, но модель не является доверенной границей. Автоматическая
запись создаёт риск неверных данных, обхода tenant scope и выполнения неподдерживаемой операции.

## Решение

AI только формирует отдельные рекомендации:

1. пользователь отправляет запрос;
2. coding service возвращает draft;
3. server action сохраняет каждую применимую рекомендацию со статусом `pending`;
4. пользователь явно подтверждает одну рекомендацию;
5. backend проверяет роль, whitelist модели/операции и DTO;
6. `domain_unified` применяет изменение и создаётся audit event.

Batch-confirm и скрытое auto-apply запрещены. Рекомендация с недостающими полями остаётся вопросом
пользователю и не сохраняется как применимая команда.

## Последствия

- Все записи имеют явного инициатора, подтверждение и audit trail.
- UI должен показывать payload/объяснение и состояния pending/confirmed/rejected.
- Повторное подтверждение должно быть идемпотентным либо отклоняться по текущему статусу.
- E2E покрывает полный путь request → pending → confirm.
